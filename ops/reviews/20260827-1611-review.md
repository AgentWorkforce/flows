## Findings

### F1 — HIGH. `flows check` is fail-open on an unresolvable deterministic command

**`sdk/src/preflight.ts:167-189`** (`warnOnUnprovableEffects`) emits a diagnostic
**only when the binary resolves** (`:181 if (exists)`). When the binary does not
resolve, and when the probe itself throws (`:177 catch`), the function emits
**nothing** — no refusal, no warning.

Reproduced from a clean checkout of the branch:

```
$ cat /tmp/pfcheck/broken.flow.yaml
version: '0.1.0'
name: broken-deterministic
steps:
  - id: build
    type: deterministic
    command: "definitely-not-a-real-binary-xyz --go"

$ node sdk/dist/cli.js check /tmp/pfcheck/broken.flow.yaml
CHECK PASSED /tmp/pfcheck/broken.flow.yaml
$ echo $?
0
$ node sdk/dist/cli.js check --json /tmp/pfcheck/broken.flow.yaml
{"ok": true, "path": "...", "resolutions": [], "diagnostics": []}
```

RFC-0001 §33-34, covenant 2: preflight "proves everything provable — spec
validity, CLI existence *and auth health* … — and **refuses or warns before the
run starts on anything it cannot prove**. Nothing may fail at minute 27 that was
checkable at minute 0." A missing deterministic binary is checkable at minute 0
and is precisely the failure class the covenant's own cited evidence describes
(`cli: grok` passing `--dry-run` and killing a run 27 minutes in). Here it passes
`check` with an empty diagnostics array.

Two aggravating details:

- The `catch` block at `sdk/src/preflight.ts:177-180` carries the comment "The
  effect claim remains unprovable whether the environment probe itself was
  unavailable or the binary resolved" — and then emits no diagnostic. The code
  contradicts its own comment: the unprovable case is the silent one.
- The predicate is inverted relative to its purpose. It warns on the case it
  *can* partially prove (binary present, effects unknown) and is silent on the
  case it cannot prove at all.

This is the clause the PR exists to close, and `ops/SCOREBOARD.md:8` now claims
it holds.

### F2 — MEDIUM. "Refuses **the ladder flows**" is not pinned by any test

RFC-0001 §96 (gate 1 done-when): "`flows check` **refuses the ladder flows** when
a declared CLI is missing or unauthenticated or a trigger has no executor."
`ops/NEXT.md` restates it: "The three ladder flows in `testdata/` are the
subjects: `flows check` must pass them clean as authored, **and refuse each one
under an induced fault**."

`sdk/tests/cli.test.ts:44-53` refuses four *separate minimal fixtures*
(`testdata/preflight/cli-{missing,unauthenticated,unresolved}.flow.yaml`,
`no-executor.flow.yaml`). No test induces a fault on `hello-ladder`,
`hello-llm`, or `hello-agent`. The behavioral-gate list in `ops/NEXT.md` and the
DRIVE-LOG "Behavioral gate" paragraph both describe fixture refusals without
noting that the ladder-refusal half of the DoD line was substituted away.

To be fair to the branch, I confirmed the **mechanism** works on a ladder flow —
copying `hello-agent.flow.yaml` and repointing its `cli` at the unauthenticated
fixture yields `REFUSED [cli_unauthenticated] … exit=2`. So this is missing
coverage plus an undisclosed substitution, not a defect. But an untested clause
is not a closed clause, and the DoD said so in its own words.

### F3 — MEDIUM. The canonical ladder specs now embed a test double

- `testdata/hello-ladder.flow.yaml:9` — `cli: ./preflight/authenticated-cli`
- `testdata/hello-llm.flow.yaml:14` — same
- `testdata/hello-agent.flow.yaml:14` — same

`testdata/preflight/authenticated-cli` is a three-line shell stub whose entire
body is `test "$1" = "auth" && test "$2" = "status"` — it exists to answer the
probe successfully. That value is now baked into
`testdata/hello-*.spec.canonical.json` and into the regenerated
`.spec.sha256` pins that gate 1's parity suites hold on both sides.

Consequences:

1. The headline behavioral evidence — "all three ladder rungs pass check",
   quoted in `ops/SCOREBOARD.md:8` — is self-certifying. It proves the in-repo
   stub answers `auth status`, not that the canonical ladder is checkable
   against anything real.
2. Covenant 1 (cofounder test — "read a stranger's flow aloud and say what it
   does"): the canonical demonstration flows for the whole rewrite now name a
   relative path into a test-fixture directory as the agent they hire.
3. The gate-1 canonical artifacts and their hashes are no longer independent of
   the test harness.

A named CLI (`claude`) on the ladder, with the probe injected in tests, or
fixture flows kept entirely separate from the canon, would have kept both the
canon and the evidence clean. `ops/NEXT.md`'s stated intent ("pass them clean
**as authored**") points the same way.

### F4 — LOW. Hardcoded, undocumented `auth status` probe contract

`sdk/src/cli.ts:167-176` spawns `<resolved-cli> auth status` for every resolved
CLI and reads exit status as auth health. Executing the declared CLI is
RFC-sanctioned (§34 requires proving "auth health"), so the execution itself is
not the objection. The objection is that the *contract a CLI must satisfy to be
preflightable* is invented here and documented nowhere — not in
`docs/SURFACE.md`, not in `sdk/src/spec.ts`'s `cli` doc-comments. Any CLI that
does not implement that exact subcommand returns non-zero and is reported as
`cli_unauthenticated`. That refusal is fail-closed, but it names a condition the
operator cannot act on, which is the covenant-1 failure mode the taxonomy exists
to avoid.

### F5 — LOW. Unreachable branch (AGENTS.md rule 6) and `--json` ignored on input failures

`sdk/src/cli.ts:54`:

```ts
if (parsed instanceof CheckFailure) return emitInputFailure(parsed, parsed.kind === 'invalid_invocation' ? undefined : args.at(-1), false, io);
```

`parseArgs` (`sdk/src/cli.ts:63-74`) returns `CheckFailure` with **only**
`'invalid_invocation'`, at both of its return sites. The `args.at(-1)` arm is
dead code — AGENTS.md rule 6, "no dead code." The same call passes `false` for
`json`, so `--json` is silently ignored on invocation failures; verified:

```
$ node sdk/dist/cli.js check --json --bogus x
REFUSED [invalid_invocation] Usage: flows check [--json] <flow.yaml|spec.json>
$ echo $?   # 2, and no JSON on stdout despite --json
```

The line is also ~150 characters against the rest of the file's style.

### F6 — LOW. The "exhaustive taxonomy" test asserts reachability, not exhaustiveness

`sdk/tests/preflight.test.ts:72-87` builds five scenarios and asserts
`new Set(refusalKinds)` equals `PREFLIGHT_FAILURE_KINDS` — i.e. *every declared
kind is reachable*. `ops/NEXT.md`'s DoD asked for the converse: "a test asserts
**exhaustively** that every refusal path returns a declared kind."

The converse does in fact hold, because `PreflightRefusal.kind` is typed
(`sdk/src/preflight.ts:38-46`) and TypeScript rejects an undeclared kind at
compile time. So the guarantee is real — but it is delivered by the compiler,
not by the test the DRIVE-LOG presents as its evidence. The
`expect(JSON.stringify(scenarios)).not.toContain('raw secret')` assertion is a
good addition and does close the leakage direction.

### F7 — LOW / observation. Dialect chosen by heuristic

`sdk/src/cli.ts:222-225` (`isKernelSpec`) decides kernel-vs-authoring dialect by
whether **any** step carries `depends_on` or `max_iterations`. Every spec the
compiler emits carries both, so this is safe today, and every misroute I could
construct failed closed with `invalid_spec`. Still, an input's dialect should not
be inferred from the presence of optional fields — a `version`/`$schema`
discriminator or an explicit flag would be the durable shape.

### F8 — Observation. The scoreboard row was flipped GREEN by the PR that implements it

`ops/SCOREBOARD.md:8` now reads **GREEN** for gate 1, citing this branch's own
72/76 test counts, before human merge and (per the branch's own DRIVE-LOG) with
no independent review having existed at authoring time. `ops/NEXT.md` asked for
"gate 1 **GREEN → AMBER** with clause 2 named as the reason, in the same PR that
then closes it"; git history never records an AMBER state — the row goes
straight from the prior GREEN to a new GREEN whose prose *narrates* an AMBER that
was never committed.

`ops/SCOREBOARD.md` is Lead-maintained reporting (`ops/RUN-CONTRACT.md:50`), not
a CI gate, so this is not a breach of AGENTS.md's "never edit a gate that judges
your own work" rail. It is noted because this tick's own assess correctly
identified the *previous* tick's same-PR GREEN as "an accounting error to
correct," and the pattern repeats here. Given F1, the GREEN is substantively
overstated: the "warns on unprovable assumptions" half of clause 2 does not hold.

## Scope and standards: what is clean

Checked and found compliant — recording it so the failures above are not read as
a blanket judgment:

- **Scope respected.** No trigger matching, dispatch, `EventFrameV1`, schedules,
  or liveness sweep. `triggers:` is inert data (`sdk/src/spec.ts:148-152`,
  `kernel/relayflowd-core/src/spec.rs:335-340`). No `flows run`/`build`/`deploy`.
  Permissions remain data-only. No live model or agent invocation. No RFC or
  charter edits. No history rewrite.
- **Fail-closed spec discipline extended on both sides.** `ROOT_KEYS` and
  `STEP_TYPE_KEYS` (`sdk/src/validate.ts:44-50`), `STEP_LLM_FIELDS` /
  `STEP_AGENT_FIELDS` (`kernel/relayflowd-core/src/spec.rs:144-151`),
  `#[serde(deny_unknown_fields)]` on `TriggerSpec`, plus new
  `EmptyCli` / `EmptyStepCli` / `InvalidTrigger` / `DuplicateTrigger` refusals.
  Both dialects reject the same malformed input.
- **`no_executor` kind name matches** what the dormant suite already expects
  (`regressions/cron-succeeded-into-void.green.flow.ts:10`), as the DoD required
  — so the regression suite needs no edit when it wakes.
- **Refusal kinds are genuinely distinct.** `cli_missing` and
  `cli_unauthenticated` are never collapsed (`sdk/src/preflight.ts:97-115`), each
  naming step id and CLI. Covenant 1 satisfied for these paths.
- **Probes are injected**, so `preflight.ts` performs no I/O
  (`sdk/src/preflight.ts:24-28`); induced faults come from committed fixture
  executables, never from mutating PATH, as the DoD required.
- **Kernel taxonomy-closure test added** and it is a real test:
  `kernel/relayflowd-core/src/machine/tests.rs:65-104` enumerates all eight
  failure `CompletionReason`s and asserts the run terminates in typed
  `RunCompletionReason::StepFailed`.
- **Structural limits held**: largest kernel `.rs` 468 lines, largest `sdk/src`
  454 (`validate.ts`, grown from 411 but still under the line).
- **`docs/SURFACE.md:78` edit is pre-authorized** by `ops/NEXT.md` ("a resolution
  that runs out of sources refuses; it never guesses a platform default") and the
  new wording is honest about what ships. Not counted against the diff.
- **`yaml` was already a runtime dependency**, so the new `bin` entry
  (`sdk/package.json:8-10`) is installable; the shebang survives `tsc` and
  `node sdk/dist/cli.js` runs.

## Verdict rationale

The bar for this review is whether the diff "honestly meets the bar and stays in
scope." Scope: yes, cleanly. Honesty of the *work*: the DRIVE-LOG's numbers are
accurate and its review disclosure is exemplary.

It fails on the honesty of the *claim*. The branch asserts, in the repository's
gate ledger, that gate 1's covenant-2 clause holds in full. Three findings say
otherwise:

- **F1** leaves a flow with a nonexistent deterministic command passing `check`
  with zero diagnostics — a fail-open in the "warns on anything it cannot prove"
  half of the very clause being closed.
- **F2** leaves the clause's literal subject — *the ladder flows*, refused under
  induced fault — untested, with the substitution undisclosed.
- **F3** makes the passing half of the evidence self-certifying against a stub
  committed into the canonical gate-1 artifacts and their hash pins.

F1 alone is sufficient: it is a covenant-2 fail-open shipped inside a covenant-2
package. Fixing it is small (emit a diagnostic on the unresolved and
probe-threw branches of `warnOnUnprovableEffects`, and decide deliberately
whether an unresolvable deterministic binary warns or refuses — RFC §34's
"refuses or warns" permits either, silence permits neither). F2 is one
parametrized test over the three ladder fixtures. F3 is a fixture-hygiene
decision the Lead should make explicitly rather than inherit from what made the
gate green.

Until then `ops/SCOREBOARD.md:8` should not read GREEN on clause 2.

REVIEW_FAILED
