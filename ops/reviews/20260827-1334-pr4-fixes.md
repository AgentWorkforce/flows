# PR #4 review fixes — kernel concurrency/lease work (llm-rung server)

Branch `flow/drive-0ba6c88-08271225`, rebased onto `origin/main`
(`aeb1c14`) before the fixes. All five review findings addressed, each
pinned by a test that fails against the pre-fix code (verified by mutation:
re-introducing each bug makes its test fail).

## Finding 1 (P1) — no per-run serialization around load-state -> next_actions -> append

**Fix.** Every mutating verb now holds a per-run mutex across the engine's
load-state -> decide -> append/execute sequence, so the scheduling decision
is atomic per run:

- `kernel/relayflowd/src/server/session.rs:89` — `ProtocolHub::run_lock`,
  a lazily-populated per-run `Arc<Mutex<()>>` map on the hub.
- `kernel/relayflowd/src/server.rs:159` (`run.resume`),
  `:214` (`step.complete`), `:245` (`event.emit`), `:254`
  (`stream.append`), plus disconnect cleanup at `:76`
  (`abandon_connection`) and the reconciler
  (`kernel/relayflowd/src/server/reconcile.rs:38`) all take the run lock
  before touching the journal. (`stream.append` also needed it: its
  read-max-offset-then-append sequence had the same race.)

**Test.** `concurrent_resumes_lease_exactly_one_attempt`
(`kernel/relayflowd/tests/crash_resume/concurrency.rs:22`): two clients
issue `run.resume` for one runnable run through a barrier against the real
`serve` binary; asserts exactly one `step.attempt.started` is journaled for
the llm step, exactly one dispatch reaches the worker, and one success
completion ends the run.

## Finding 2 (P1) — live `run.resume` marks running attempts crashed mid-lease

**Fix.** Live resume now distinguishes active hub assignments from
genuinely dead attempts; only attempts whose lease deadline passed or whose
worker is detached are recovered:

- `kernel/relayflowd-core/src/machine.rs:265` —
  `recovery_actions_filtered(state, now_ms, lease_is_active)`; the
  unconditional `recovery_actions` (`:257`) delegates with a constant
  `false` (offline resume: no server, no live lease).
- `kernel/relayflowd/src/worker.rs:37` — `LeaseProbe` trait;
  `kernel/relayflowd/src/server/session.rs:320` implements it on the hub
  (assignment present and its renewed deadline not passed).
- `kernel/relayflowd/src/engine/remote.rs:81` — `Engine::resume_live`,
  used by the `run.resume` verb (`kernel/relayflowd/src/server.rs:170`);
  shared plumbing in `kernel/relayflowd/src/engine.rs:150`
  (`resume_filtered`).
- `kernel/relayflowd/src/engine.rs:245` — when a resume finds only a live
  out-of-band attempt (no other actions), the run keeps registry status
  `waiting_worker` with its lease deadline instead of being re-parked.

**Test.** `live_resume_leaves_an_active_lease_running`
(`kernel/relayflowd/tests/crash_resume/concurrency.rs:79`): with a
dispatched, heartbeating attempt mid-lease, `run.resume` journals no
crashed completion and no duplicate attempt start, and the original
worker's `step.complete` still finishes the run.

## Finding 3 (P1) — no sweep of expired leases; hung worker waits forever

**Fix.** Lease renewal is recorded durably and an expiry reconciler
abandons attempts whose heartbeats stopped past the deadline:

- `kernel/relayflowd/src/server/reconcile.rs:24` (`spawn_reconciler`,
  started by `serve` at `kernel/relayflowd/src/server.rs:45`) sweeps every
  250ms; `reconcile_pass(:38)` takes time as a parameter (simulated-clock
  testable), re-checks the lease under the run lock, journals a
  `step.completed` with `completionReason: lease_expired` via
  `abandon_out_of_band`, releases the assignment only after the journal
  write succeeds, and re-drives the run (`redrive`, `:99`) so the step is
  leased again.
- `kernel/relayflowd/src/server.rs:210` + 
  `kernel/relayflowd/src/engine/remote.rs:130` +
  `kernel/relayflowd-journal/src/registry.rs:68` — `step.heartbeat` now
  persists the renewed deadline (`Registry::renew_deadline`) and fails
  closed: a failed durable write fails the heartbeat. The journal pins the
  lease grant at attempt start; the sweep runs against that deadline until
  a renewal extends it.
- `kernel/relayflowd/src/server/session.rs:211` — `expired_assignments`.

**Test.**
`stopped_heartbeats_past_the_deadline_journal_lease_expired_and_release_the_step`
(`kernel/relayflowd/src/server/tests.rs:131`): a worker takes a dispatch,
heartbeats once (backdated 40s — then hangs with the socket open). A sweep
inside the lease abandons nothing; a sweep past the deadline journals
exactly one `lease_expired` completion with `disposition: retry`, is
idempotent, and a subsequent resume leases attempt 2 to the same attached
worker — the step is runnable again.

## Finding 4 (P2) — replay-then-watch gap loses entries forever

**Fix.** `run.watch` registers the watcher BEFORE replaying
(`kernel/relayflowd/src/server.rs:305`, `watch_with_replay`): the watcher
starts in a buffering mode
(`kernel/relayflowd/src/server/session.rs:33`, `WatchDelivery`), live
appends buffer keyed by journal seq, then the replay reports the sequence
cursor it covered (`watch_ready`, `:134`) and buffered entries are flushed
deduped against that cursor. A replay failure unregisters the watcher
(fail closed) instead of leaving it buffering forever.

**Test.** `an_entry_appended_during_watch_registration_is_delivered_exactly_once`
(`kernel/relayflowd/src/server/tests.rs:185`): uses the `after_register`
ordering seam to interleave an append inside the registration window, plus
a post-replay live append; asserts the watcher receives every journal
entry exactly once, in order, with no duplicate frame.

## Finding 5 (P1) — disconnect cleanup swallows journal failures (`let _ =`)

**Fix.** `kernel/relayflowd/src/server.rs:76` (`abandon_connection`): a
failed journal append for the crashed completion is logged at error level
AND the abandonment is retained
(`ProtocolHub::queue_abandonment`,
`kernel/relayflowd/src/server/session.rs:227`) for the reconciler, which
retries it every sweep until the journal records the completion
(`kernel/relayflowd/src/server/reconcile.rs:38`, second phase).
`Engine::abandon_out_of_band`
(`kernel/relayflowd/src/engine/remote.rs:93`) now returns
`Ok(None)` when the attempt is no longer the active lease (already
resolved elsewhere — retrying would be wrong) while journal/IO failures
stay hard errors, so the retry loop can terminate correctly without ever
dropping an unrecorded abandonment.

**Test.** `a_failed_disconnect_journal_append_is_retained_and_retried_not_dropped`
(`kernel/relayflowd/src/server/tests.rs:255`): the run journal is made
unreachable when the worker's connection dies; asserts nothing was
journaled AND nothing was dropped (the queued abandonment survives), then
the reconciler journals exactly one `crashed` completion once the journal
heals, and a second pass has nothing left to record.

  the same protocol surface, and all 54 SDK tests pass unchanged.

  clock (`reconcile_pass` takes `now_ms`) because the journaled lease
