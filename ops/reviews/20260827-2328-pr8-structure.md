`cli`/`triggers`/`TriggerSpec` appear **only** in `spec.rs` (parse + serialize + structural validation) and its tests. The execution path (`machine.rs`, `state.rs`, `journal.rs`, `verify.rs`, `retry.rs`, `clock.rs`) never reads them. The kernel does not invoke a CLI, does not match a trigger, does not dispatch. The inline comments fence this explicitly ("The kernel treats this as inert data; `run.start` does not invoke the surface preflight"; "Inert gate-1 declarations. Matching and dispatch belong to gate 2").

This is the right structural call, and it is **required** by RFC-0001, not a relaxation of it:
- Decision #5: "the composable unit is the spec + journal protocol."
- Decision #14: `flows build` seals a **canonical spec JSON** into a content-addressed bundle; "runs reference digests, never working trees."
- The kernel inlines the spec in `run.spawned` (RFC §1).

If preflight declarations (`cli`, `triggers`) lived in a sidecar outside the spec, they would be outside the sealed bundle, and `flows check` could not run on a digest-pulled bundle. Carrying them as inert data **on** the kernel spec preserves the single-sealed-artifact invariant. The new test `preflight_data_is_fail_closed` pins that the kernel holds them as a **closed** shape (`#[serde(deny_unknown_fields)]` on `TriggerSpec`; unknown `worker` rejected) — so the kernel is not absorbing an open surface vocabulary, only a closed data carrier. Consistent with decision #13 (closed kernel vocabulary) and AGENTS.md rule 2 (kernel is small and pure, no product logic).

The added validation (`EmptyCli`, `InvalidTrigger`, `DuplicateTrigger`, `EmptyStepCli`) is the same class as the kernel's existing `EmptyStepId`/`DuplicateStep`/`ZeroIterations` — structural data-shape validation of the boundary contract, fail-closed. Not product logic.

**No provider SDKs, no tenant awareness, no I/O entered the kernel.** The actual CLI probing, auth-status checking, and executor-registration checking all live in the SDK (`preflight.ts` does the logic with injected probes; `cli.ts` binds real I/O). The boundary is clean: **kernel = inert data carrier + closed-shape validation; SDK = I/O + preflight logic.**

## 6. Findings

### F1 — `cli.ts` mixes five concerns (low severity)
`sdk/src/cli.ts` combines: (1) arg parsing (`parseArgs`), (2) flow reading/dialect detection (`readFlow`/`kernelDialectMarker`), (3) project-config discovery (`findConfig`/`readProjectConfig`), (4) the **system-probe implementation** (`probeCli`/`resolveExecutable`/`classifySpawnFailure`/`executableExists` — ~50 lines of `spawnSync` process logic), and (5) report emission (`emitReport`/`emitInputFailure`). `preflight.ts` was deliberately kept I/O-free by injecting `PreflightProbes`; `cli.ts` then owns both the probe *implementation* and the orchestration + reporting in one file. A cleaner split: extract the process-spawning probe implementation into a `probes.ts` (or `system-probes.ts`), leaving `cli.ts` as orchestration + emission. Not a blocker — the file is 311 lines and each function is small and named — but it is the clearest single-purpose violation in the PR.

### F2 — `validate.ts` approaching the 500-line smell line (low severity / watch)
At 454 lines `validate.ts` is the closest file to AGENTS.md's 500-line design smell. It is cohesive (one `Validator` class + `nearestKey`/`levenshtein` typo helpers + predicates), and the typo-suggestion block (~35 lines) is tightly coupled to the validator's error messages, so it is not yet a split candidate. Flag as a watch: the next validation concern that lands here (e.g. narrowing `steps: []`, or new gate/permission rules) should trigger an extract, not an append.

### Watch — `compile.ts` now holds both dialect directions (observation, not a finding)
`compile.ts` (408) now contains `compileSpec`/`toKernelSpec` (authoring→kernel) and the new `kernelToAuthoring` (kernel→authoring, ~160 lines). The two are inverses sharing dialect knowledge, so co-location is defensible and keeps the boundary-shape knowledge in one place. If a third direction or richer kernel-shape handling lands, consider a `dialect/` subdirectory. No action now.
