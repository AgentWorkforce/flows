## Blocking findings

### H1 — WP-7 repeats the false-comparison-point mistake that the preceding history review rejected

`ops/NEXT.md:223-228` says both scope guards **must print nothing**, including:

```text
git diff origin/main HEAD -- kernel/        # this package changes no kernel code
```

That command is not empty at the reviewed head:

```text
M  kernel/relayflowd-core/src/machine/tests.rs
M  kernel/relayflowd-core/src/spec.rs
M  kernel/relayflowd-core/src/spec/tests.rs
```

Those are the earlier PR #8 Gate-1 parity changes, not WP-7 changes. The
package-local guard is the one that actually proves WP-7's claimed scope:

```text
$ git diff --name-status b43cd0f HEAD -- kernel/
# empty
```

The durable log knows this. `ops/DRIVE-LOG.md:1642-1648` substitutes
`b43cd0f..HEAD`, explicitly says the literal work-package command still lists
three kernel files, and calls the mismatch a **baseline contradiction**. The
controlling work package nevertheless still says the false command must be
empty and Definition of Done item 12 says the package is not done when a lens
rejects.

This is the same failure class recorded only minutes earlier. The history
review at `1bf885f` rejected WP-6 because `ops/NEXT.md` required an
`a8c9110..HEAD` product diff to be empty even though WP-6 itself had changed
`docs/SURFACE.md`. Commit `a5e58d7` repaired that by using the correct binding
point. WP-7 has now repeated the mistake with `origin/main..HEAD` versus its
package-local kernel scope. Passing it would teach the record that a command
may be declared green while its own output is known to be non-empty.

History-consistent repair: keep the `origin/main..HEAD` workflow guard because
the PR must not edit its judge, but change the kernel guard to the WP-7 binding
point (`b43cd0f..HEAD`, or another explicitly justified pre-WP-7 head). Update
the controlling record and append the correction to the drive chronology; do
not remove the earlier kernel changes or rewrite the log. The next history
review must bind to the repaired head.
