At the previous PR #131 head, Bun compilation created another packaging form
that the import-safety guard did not recognize, reproducing the same observable
effect: success, zero stdout, and no CLI work. The repaired source separates
the two concerns cleanly:

```ts
// sdk/src/cli-executable.ts
import { runCli } from './cli.js';

async function main(): Promise<void> {
  process.exitCode = await runCli(process.argv.slice(2));
}

void main().catch((error: unknown) => {
  process.stderr.write(`${error instanceof Error ? error.message : String(error)}\n`);
  process.exitCode = 1;
});
```

There is no invocation predicate in this entry module. The workflow compiles
this exact file with `--compile --target=bun-linux-x64`; `cli.ts` remains safe
for imports and its existing Node-distribution symlink behavior remains pinned
by `sdk/tests/bin.test.ts`.
