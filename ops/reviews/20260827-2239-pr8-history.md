## Blocking finding

### H1 (P1) — the new disclosure contradicts both the implementation and the durable history

`18f03be` adds this public contract to `docs/SURFACE.md`:

```text
**Accepted deterministic-command limitation (Codex P1):** `flows check`
warns with `unprovable_effects`, rather than refusing, when a deterministic
command's first word cannot be resolved.
```

That warning kind is false for the condition the sentence names. The settled
three-way taxonomy is:

- `unprovable_effects` when the first word **does resolve**, but its effects
  cannot be proven;
- `command_unresolved` when the first word **does not resolve**;
- `command_unprovable` when the word cannot be extracted or the probe cannot
  be completed.

This is not an interpretation inferred from a test name. The current source
and the append-only drive record say the same thing, while the new paragraph
says the opposite:

```text
$ rg -n "kind: 'unprovable_effects'|kind: 'command_unresolved'|kind: 'command_unprovable'" sdk/src/preflight.ts
247:      kind: 'command_unprovable',
259:      kind: 'command_unprovable',
268:      kind: 'unprovable_effects',
274:      kind: 'command_unresolved',

$ sed -n '590,601p' ops/DRIVE-LOG.md
The repair (16:20) answered all three by changing code, not by re-arguing:
`sdk/src/preflight.ts:167-213` now leaves exactly one warning on **every**
deterministic step across all three knowable states (`unprovable_effects`,
`command_unresolved`, `command_unprovable`, the latter two declared in
`sdk/src/failure-kinds.ts:23-33`); warn-not-refuse was chosen because
`kernel/relayflowd/src/exec_det.rs:22-27` runs string commands through
`/bin/sh -c`, so an unresolved first word may be a builtin — the executor was
read, not assumed.
```

I also exercised the unresolved branch directly against the built current-tree
module. This is a behavioral reproduction, not a mutation claim:

This repeats a mistake the log already records: the original WP-4 review
rejected a silent unresolved-command path, and the repair deliberately created
and documented three distinct warning states. The post-review commit now
collapses two of those states in the public explanation. That violates the
repository's evidence rule and RFC covenant 1's requirement that errors use the
author-facing vocabulary truthfully. A reader following `SURFACE.md` would
look for the wrong declared diagnostic.

**Required fix:** change only the diagnostic name in this sentence from
`unprovable_effects` to `command_unresolved` (or avoid naming a kind while
describing the behavior accurately). The warn-not-refuse decision, shell
rationale, backlog pointer, and statement that `cli_missing` is for declared
LLM/agent CLIs all fit the recorded design and should remain. No code change or
RFC change is called for by this finding.
