# Structure review — PR #8

- **Lens:** structure (boundaries, coupling, file size & single purpose, RFC-0001 / AGENTS.md shape)
- **Reviewer:** structure lens (review-swarm `lens-structure`, opencode/glm-5.2)
- **Verdict:** REVIEW_PASSED (with two watch items)

## What this PR changes

- **Kernel (`kernel/relayflowd-core`):** `spec.rs` gains two inert spec fields —
  `cli: Option<String>` (flow-level default CLI for llm/agent steps) and
  `triggers: Vec<TriggerSpec>` (`TriggerSpec { id, executor }`) — plus shape
  validation (`EmptyCli`, `InvalidTrigger`, `DuplicateTrigger`, `EmptyStepCli`)
  and `cli` on the `Llm`/`Agent` step kinds. `machine/tests.rs` adds a test
  pinning that every declared failure kind terminates the run with a typed
  `completionReason`. `spec/tests.rs` adds parse/validate coverage.
- **SDK (`sdk/src`):** new `preflight.ts` (pure, injected probes), new
  `failure-kinds.ts` (closed refusal/warning taxonomy), new `cli.ts` (the
  `flows check` command), `compile.ts` gains `kernelToAuthoring` (the inverse
  of `toKernelSpec`), `validate.ts`/`spec.ts`/`index.ts` carry `cli`/`triggers`
  through with fail-closed validation.
- **Docs/meta:** `docs/SURFACE.md` documents the preflightable-CLI contract;
  `workflows/review-swarm.yaml` defines the three-lens review swarm;
  `ops/*` and `ops/reviews/*` hold drive-log and prior review transcripts.

## Lens 1 — Kernel purity (AGENTS.md #2, #3; RFC §4)

**Clean.** `cli` and `triggers` (incl. `TriggerSpec.executor`) are carried
**inertly** on `RunSpec`. The kernel validates their *structural shape*
(non-empty, unique ids) and nothing more. It never resolves, probes, matches,
or dispatches them.

Verified by search: `cli` / `triggers` / `TriggerSpec.executor` appear **only**
in `spec.rs` and its tests. The `executor` referenced at `entry.rs:127`
(`AttemptStartedPayload.executor`) and `machine.rs:218` is a **different,
pre-existing** field — the *step* executor, set to `"kernel"` (deterministic)
or `"unassigned"` (llm/agent) — and is untouched by this PR. No conflation.

No provider SDKs, no I/O, no product logic, no tenant awareness entered the
kernel. The actual resolution (CLI existence/auth, executor registration) lives
in `sdk/src/preflight.ts` — exactly where RFC gate 1 puts it: *"`flows check`
refuses … a declared CLI is missing or unauthenticated or a trigger has no
executor."* The boundary is respected.

This is defensible against the "no product logic in the kernel" rule: the spec
is the boundary artifact (settled decision #5: "the composable unit is the spec
+ journal protocol"), the kernel owns the spec schema, and carrying an inert
declaration is not acting on it. The `on` resident verb is kernel vocabulary
(decision #13), so triggers-as-a-concept belong at the boundary; matching and
dispatch remain gate 2, and the code says so inline (`spec.rs:38`: *"Inert
gate-1 declarations. Matching and dispatch belong to gate 2."*).

## Lens 2 — Helpers over primitives (RFC decision #13; AGENTS.md #6)

**Clean.** The kernel vocabulary stays closed: step verbs are still
`deterministic` / `llm` / `agent`; resident verbs `on`/`human`/`dispatch`/`done`
are unchanged. This PR adds **no new primitive**:

- `preflight` is a **surface helper** in the SDK, not a kernel mechanism.
- `failure-kinds.ts` is a closed **surface taxonomy**, not a kernel enum.
- `kernelToAuthoring` is a **compiler inverse** (boundary translation), not a
  primitive.
- `TriggerSpec` is a **data shape** on the spec, not a new step verb or kernel
  operation.

No speculative abstraction. `cli` is a declarative attribute on llm/agent, not
a step type. Good.

## Lens 3 — Fail-closed + completionReason discipline (AGENTS.md #4; RFC covenant 2)

**Strong, and newly test-pinned.**

- Kernel `spec.rs` fails closed on empty cli, invalid/duplicate triggers, empty
  step cli (`SpecError` variants); `TriggerSpec` is `deny_unknown_fields`.
- `machine/tests.rs::every_failed_run_terminates_with_declared_completion_reasons`
  iterates **every** declared `CompletionReason` (VerificationFailed,
  RetriesExhausted, LeaseExpired, Crashed, Timeout, WorkerError, BudgetExceeded,
  Canceled), asserts the `StepCompletedPayload.completion_reason` is the typed
  enum, then folds the journal and asserts the run terminates with
  `RunCompletionReason::StepFailed`. This is exactly the "every completion
  carries a `completionReason`; a raw stack trace is a kernel bug" discipline.
  The test references only real, existing types — it is not dead code.
- SDK `validate.ts` keeps its fail-closed-on-unknown-keys discipline and adds
  `validateTriggers` / `validateCli`.
- `preflight.ts`: a probe that throws becomes a `probe_failed` **refusal**, never
  a silent success. A deterministic step always leaves exactly one warning
  (resolved / unresolved / unprovable) — *"silence is not one of the states."*
- `cli.ts`: unreadable input, invalid YAML, invalid spec, invalid config all
  become typed refusals (`input_unreadable`, `invalid_spec`, `config_invalid`);
  exit 2 on refusal, 0 on pass.
- `compile.ts::kernelToAuthoring`: unknown or malformed kernel keys throw
  `CompileError` — *"Unknown keys and malformed kernel-only policy fields fail
  closed."*
- `docs/SURFACE.md` documents the `<cli> auth status` contract and states
  preflight *"never sends a prompt, never spends a token"* — the boundary
  between preflight (prove) and execution (do) is explicit.

## Lens 5 — Vocabulary & boundary parity (AGENTS.md #7; RFC §1)

**Clean.** Step types remain `deterministic` / `llm` / `agent`. Journal entry
names are unchanged. `TriggerSpec { id, executor }` matches kernel↔SDK
(`spec.rs` ↔ `spec.ts`). The spec-parity test adds a **round-trip** assertion
(`kernelToAuthoring(toKernelSpec(flow)) === flow`) that structurally enforces
the boundary dialect mapping is an involution — good discipline that prevents
the two sides from drifting.

## Observations (non-blocking)

1. **Trigger-shape validation is duplicated** kernel-side
   (`SpecError::InvalidTrigger` / `DuplicateTrigger`) and SDK-side
   (`validateTriggers`). Defense-in-depth at the boundary is reasonable, and the
   kernel owns the spec schema so validating declared fields is in-scope — but
   since the kernel never dispatches triggers (gate 2 does), the kernel's
   trigger-shape validation leans toward surface concern. Acceptable today;
   revisit when gate 2 lands.
2. `validate.ts` tightened version checking from a semver regex to **exact
   match** against `SPEC_SCHEMA_VERSION`. Correct for gate 1 (no N−1 window
   yet), but RFC §7 lists the version window as an open question — track that
   the exact-match will need to relax when a second schema version appears.
3. `cli.ts::probeCli` assumes `<cli> auth status` exists. That is a product
   assumption about CLIs (claude/codex/gemini), but it lives in the surface and
   is fail-closed (a CLI without `auth status` exits non-zero →
   `cli_unauthenticated`, not assumed healthy). `SURFACE.md` now documents it as
   the contract. Fine.

## Conclusion

The shape matches RFC-0001 and AGENTS.md. The kernel stays small and pure —
`cli`/`triggers` are inert declarations, validated for shape, never acted on;
no provider SDKs, no I/O, no product logic, no tenant awareness leaked in. No
primitive was added where a helper belonged; preflight is a surface helper and
the kernel vocabulary stays closed. Fail-closed and `completionReason`
discipline are strong and now pinned by a kernel test that covers every declared
failure kind. File sizes are within bounds, with `validate.ts` (454) and
`spec.rs` (451) flagged as watch items to split before they cross 500.

I did not re-run the kernel build or the test suite — this review examined the
diff structurally; the gate run is a separate concern.

REVIEW_PASSED
