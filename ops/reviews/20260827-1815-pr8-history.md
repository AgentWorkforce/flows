## Blocking findings

### H1 — the PR edits the gate that is being used to judge the PR, repeating a recorded self-certification failure

`930f376` adds `workflows/review-swarm.yaml` to the PR and changes the judging
procedure materially: the lenses are serialized, each lens is instructed to
commit its own transcript, and the aggregate now verifies that each transcript
exists in `HEAD`. These are sensible changes in isolation, but they are being
made by PR #8 and immediately used to certify PR #8.

The package that produced `930f376` makes the circularity explicit. Its
assessment artifact (`9555d6d:ops/NEXT.md`) sets the objective to bring PR #8
to a state where this same `workflows/review-swarm.yaml` returns
`SWARM_PASSED`; lists that workflow as an editable file; then requires the
changed workflow to be rerun against PR #8. The current review run is already
executing the new instructions from that patch.

That contradicts two settled rails:

- `AGENTS.md`: **“Never edit a gate that judges your own work.”**
- RFC-0001 settled decision 6: **“no gate may be editable by the agents it
  judges.”** RFC §2 also says gate definitions are owned outside the mutating
  agent's write scope.

This is not a novel edge case. The history records the same failure class:

- `ops/DRIVE-LOG.md` describes PR #8's earlier F3 as a “self-certifying
  behavioral gate” whose stub was committed into the artifacts it certified.
- The same log later explains why the WP-4 repair correctly did **not** edit
  `workflows/drive.yaml`: it was the gate judging that work.
- `ops/NEXT.md` repeats both facts: the prior self-certifying gate was a review
  failure, and the judging workflow was explicitly out of scope.

The new workflow may be better than the old workflow, but a better
self-selected judge is still a self-selected judge. The evidence chain is
circular, so a passing result from this run cannot clear the PR.

The history-consistent repair is to land the review-swarm durability change
outside PR #8 and outside the work it judges (for example, as an independently
reviewed gate change on `main`), then run that already-owned, unchanged gate
against PR #8. PR #8 must not carry the gate change used as its own proof.

### H2 — the latest commit's work package is not in the PR's ancestry, while the committed `ops/NEXT.md` says its source edits are forbidden

At the supplied PR head, `ops/NEXT.md` still declares **WP-4-FIX** as the
single highest-priority package. It says “No other file may change. In
particular: nothing under `sdk/src/` or `kernel/`,” and repeats under Explicitly
OUT of scope that any `sdk/src/**` change is forbidden.

The latest commit is instead named **WP-5** and changes:

- `sdk/src/cli.ts`
- `sdk/src/compile.ts`
- `sdk/src/index.ts`
- `sdk/src/validate.ts`
- SDK tests, docs, ops records, and `workflows/review-swarm.yaml`

There is a detailed WP-5 assessment at local commit `9555d6d`, and its content
does explain these edits. But `9555d6d` is **not an ancestor of `930f376`** and
is contained only by the local `flow/drive-45cc352-08271751` branch. It is not
part of the supplied diff or the PR's durable history. A future reader of PR #8
therefore sees a `WP-5` subject with no WP-5 plan, while the authoritative
`ops/NEXT.md` in that same tree expressly forbids the source changes it made.

That repeats the repository's recorded process drift around local-only assess
artifacts and code landing under commits/plans that do not name or authorize
the work. It also repeats the evidence-loss lesson that motivated WP-5 itself:
an artifact outside the durable branch history is not durable evidence.

`930f376`'s subject is directionally honest—it does address the previously
enumerated F0-F5 findings—but it does not make the branch's committed story
true. The PR title is now incomplete as well: a PR titled as the WP-4 preflight
also carries a material rewrite of its own review infrastructure.

Those corrections are valuable, but they do not override H1. RFC-0001 makes
gate ownership an integrity invariant, not a warning that can be balanced
against otherwise good changes. H2 independently leaves the commit series
without a durable, internally consistent work-package narrative.

## Verdict

PR #8 does not yet fit the story of the code. It repeats the previously
recorded self-certification mistake by modifying and immediately relying on
its own judging gate, in direct conflict with RFC-0001 settled decision 6 and
`AGENTS.md`. Its latest work package also exists only off-branch while the
committed package forbids the source edits made under the `WP-5` subject.
