- kernel validation rejects workspace spellings containing empty, dot, dot-dot, trailing-slash, or surrounding-whitespace aliases;
- the scheduler gives canonical workspace paths subtree-aware identities and continues to isolate Workspace from External identities;
- worker.attach rejects non-canonical workspace pins;
- the SDK applies the same lexical canonical-path predicate; and
- the new kernel, real-socket, and SDK tests pass and fail under the requested source mutations.

However, the same commit makes the repository's canonical hello ladder invalid. Existing kernel
unit coverage, the SDK compiler test, the shared SDK/kernel spec-parity fixture, and the CLI check
all still declare workspace surface repo/. The new contract explicitly rejects that spelling.
This is a newly introduced cross-kernel/SDK compatibility regression in the exact surface being
changed, and it leaves the Gate 1 canonical ladder red. Signoff is blocked.
