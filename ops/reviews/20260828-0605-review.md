## Findings

### F1 (blocking) — B1.3's mechanism is inverted, and its line citation points at unrelated code

`ops/NEXT.md:113-118`:

> **NaN escape.** `lease_deadline_ms` is populated only when the registry row
> reads `waiting_worker` (`engine.rs:341-350`). A `running` step whose row
> says anything else yields `Number.NaN` […]

Both halves are false, and the citation is wrong.

**Wrong citation.** `kernel/relayflowd/src/engine.rs:341-350` at `f552cce` is
`fn open_run`, `fn registry`, and `fn run_path` — nothing to do with lease
deadlines. The lease-deadline code is `engine.rs:176-181`.

**Inverted mechanism.** `snapshot_from_state`
(`kernel/relayflowd/src/engine/model.rs:86-91`) populates the field for
*every* `Running` step, unconditionally:

```rust
StepState::Running { lease_deadline_ms, .. } => (StepStatus::Running, Some(lease_deadline_ms)),
```

`Engine::snapshot` (`engine.rs:176-181`) then *overrides* that value only
when the registry row reads `waiting_worker`:

```rust
if let Some(record) = registry_record.filter(|record| record.status == "waiting_worker") {
    for step in snapshot.steps.values_mut().filter(...Running...) {
        step.lease_deadline_ms = record.next_wake_at_ms;   // Option<i64>
    }
}
```

`next_wake_at_ms` is `Option<i64>` (`registry.rs:16`), inserted as `NULL`
(`registry.rs:41-43`) and set only by `renew_deadline`, which itself requires
`status = 'waiting_worker'` (`registry.rs:74-76`). `StepSnapshot`
(`engine/model.rs:36-38`) carries `#[serde(skip_serializing_if = "Option::is_none")]`.

Therefore the NaN arises **precisely when the row DOES read `waiting_worker`**
with `next_wake_at_ms` still NULL — the branch clears a deadline the state
machine had already supplied. A `Running` step whose row says *anything else*
keeps `Some(..)` from `model.rs:91` and is finite. The assessment states the
exact opposite.

**Why this is blocking, not cosmetic.** Builder done-when clause 3
(`ops/NEXT.md:190-194`) mandates a regression that is **red before the fix**.
A builder following the stated mechanism will construct a `running` step with
a non-`waiting_worker` registry row, expecting
`throw new Error('running step "..." omitted lease_deadline_ms')` from
`sdk/src/cli/run.ts:288-290`. That case emits a finite deadline and does not
throw. The test goes green before the fix, cannot be captured red, and clause
3 is unsatisfiable as written. The work package sends the builder to build a
non-reproducing regression for a defect that is real.

The *required behaviour* bullet for B1.3 (`ops/NEXT.md:127-129`) remains
sound. Only the mechanism and citation are wrong.

This is the failure class `AGENTS.md` § "Evidence is captured, not narrated"

every branch") that a reviewer checks and finds does not hold. Clause 3 —
"Cite paths that exist… a wrong one reads as fabrication even when the work is
real" — applies in its mirror image here: a path asserted absent that is
present reads the same way.

**Compounding, and the practical cost.** The file's content is itself a
reconstruction notice, headed *"This file is **not** the original 05:12 review
transcript"* and closing `BLOCKING_FINDINGS_RECONSTRUCTED`. So the assessment's
*substance* — the original transcript is unrecoverable — holds, and its

untracked**. Because the assessment reports it absent, the builder is directed
to author a duplicate at a path already occupied, and done-when clause 6
("The 0512 transcript question is resolved in the repo") is aimed at the wrong
action. The correct instruction is one word different: `git add` the file that

## Rationale

The assessment is strong: its two findings are real defects verified against
the committed tree, its external facts are exact to the digit, and its
out-of-scope section shows genuine restraint. If the bar were "are B1 and B2
worth the next tick," this passes easily.

The bar is not that. `AGENTS.md` states it directly: *"The code being right
does not rescue a report that is wrong. A reviewer can only judge what it can
check."* Two things I checked came back wrong. F2 is an evidence claim about
the reviewer's own diligence, refuted by a file at the exact path it declares
empty — and this repo has an explicit, hard-won standard against precisely
that. F1 misstates a code mechanism in the direction that makes a mandated
done-when clause unsatisfiable, sending the builder to write a regression that
cannot go red.

Both are cheap to fix — correct B1.3 to name `engine.rs:176-181` and the
`waiting_worker`-with-NULL-`next_wake_at_ms` path; replace the F2 paragraph
with an instruction to `git add` the reconstruction note that already exists;
disambiguate the §4 sentence. None of that requires re-deriving the work
package. But an assessment that misreports its own evidence check is the
failure this repo has rejected six consecutive rounds for, and passing it here
would say the standard is negotiable when the surrounding work is good.

REVIEW_FAILED
