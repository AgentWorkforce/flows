## Blocking finding

### S1 — HIGH — the final artifact verifier does not enforce the `bin/flows` platform contract

The boundary is split asymmetrically:

- `buildCloudArtifact` checks `relayflowd` and `flowsExecutable` with
  `assertLinuxX64Elf` at `scripts/cloud-artifact.mjs:32-33`.
- `verifyArtifactDirectory`, the shared verifier used after staging and after archive
  extraction, checks only `bin/relayflowd` at line 118.
- The PR body promises that **both** executables must be Linux x64 ELF files.
- The negative ELF regression at `scripts/cloud-artifact.test.mjs:118-131` covers only
  `relayflowd`; there is no equivalent `bin/flows` case.

This is not a claim that the current CI artifact is broken: the current builder checks
and the Ubuntu smoke executes the real standalone `flows`. It is a boundary defect:
`verifyCloudArtifact` can approve an artifact that violates the manifest's advertised
runtime target whenever the digest, file hashes, paths, and modes are internally
consistent. An alternative producer or a future refactor that bypasses/removes the
builder-side precheck would still receive a green verifier and green tests.

Literal independent probe (the manifest digest is restamped, and both modes remain
executable):

```sh
node --input-type=module <<'NODE'
import { createHash } from 'node:crypto';
import { chmod, mkdir, mkdtemp, readFile, rm, writeFile } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { join } from 'node:path';
import { verifyArtifactDirectory } from './scripts/cloud-artifact.mjs';
const root = await mkdtemp(join(tmpdir(), 'pr131-flows-boundary-'));
try {
  await mkdir(join(root, 'bin'));
  const relayflowd = Buffer.alloc(64);
  relayflowd.set([0x7f, 0x45, 0x4c, 0x46, 2, 1], 0);
  relayflowd.writeUInt16LE(62, 18);
  await writeFile(join(root, 'bin', 'relayflowd'), relayflowd);
  await writeFile(join(root, 'bin', 'flows'), '#!/bin/sh\necho not-an-elf\n');
  await chmod(join(root, 'bin', 'relayflowd'), 0o755);
  await chmod(join(root, 'bin', 'flows'), 0o755);
  const digest = async (path) => createHash('sha256').update(await readFile(path)).digest('hex');
  const manifest = {
    schemaVersion: 1, protocolVersion: '0', sourceCommit: 'a'.repeat(40),
    platform: 'linux', arch: 'x64',
    files: [
      { path: 'bin/flows', sha256: await digest(join(root, 'bin', 'flows')), executable: true },
      { path: 'bin/relayflowd', sha256: await digest(join(root, 'bin', 'relayflowd')), executable: true },
    ],
  };
  await writeFile(join(root, 'manifest.json'), `${JSON.stringify(manifest)}\n`);
  await verifyArtifactDirectory(root);
  console.log('RESULT: verifier accepted executable non-ELF bin/flows');
} finally {
  await rm(root, { recursive: true, force: true });
}
NODE
```

Captured output:

```text
RESULT: verifier accepted executable non-ELF bin/flows
```

Minimum repair: have `verifyArtifactDirectory` call `assertLinuxX64Elf` for both
required executables, and add the symmetric restamped-non-ELF `bin/flows` regression.
Keeping the early builder checks is reasonable preflight; the final shared verifier
must own the complete artifact contract.
