## 5. Residual findings (non-blocking)

### P2-A — a step pinned to a surface the attached worker does not hold burns one journaled attempt per resume, forever

`kernel/relayflowd/src/engine.rs:316-328` (`agent_pins_available`) vs
`kernel/relayflowd/src/server/session.rs:353-355` (`worker_holds`)

The preflight and the dispatch gate disagree once a step has started at least once.
`agent_pins_available` takes `last_start_pins` when present, finds the pin set fully covered, never
consults a worker, and answers "dispatchable". `dispatch` then asks whether the *currently selected*
worker reports those surfaces, and declines. The attempt-started entry has already been journaled,
so each resume leaves an orphan attempt behind.

Reproduced by extending `a_replacement_worker_that_never_reported_the_pinned_surface_is_not_dispatched_to`
(probe reverted; the file is byte-identical to HEAD):

```
PROBE after 1st resume: starts=2
PROBE resume 2: ok=true status="parked" starts=3 registry="parked"
PROBE resume 3: ok=true status="parked" starts=4 registry="parked"
PROBE resume 4: ok=true status="parked" starts=5 registry="parked"
PROBE resume 5: ok=true status="parked" starts=6 registry="parked"
PROBE completions: [(Crashed, Retry), (Crashed, Retry), (Crashed, Retry), (Crashed, Retry), (Crashed, Retry)]
```

The spec declares `max_iterations: 3`, but it never binds: `abandonment_actions` gates on
`semantic_executions` (`recovery.rs:82`) and a crashed attempt correctly consumes none. So the loop
does not converge — it grows the journal by three entries per resume and never terminates in a
declared failure kind.

Why this is not a block: the run stays at registry status `parked`, which is the honest answer
("nothing is coming until something changes"); no effect is performed, no work is lost, nothing
fails open, and the run heals the instant a worker holding the surface attaches. It is also not
reachable in the shipped rung-(c) flow, whose worker always holds `repo`. But it is the same class
the package set out to close in P1-3 — an incompatible worker should park *without* starting an
attempt — and the fix is small: have `agent_pins_available` route through the same worker resolution
`dispatch` will use (i.e. also require `worker_holds`), so the preflight and the gate cannot
disagree.

### P3-B — non-agent completions still journal unvalidated `started_pins` / `end_pins`

`kernel/relayflowd/src/engine/remote.rs:72-84`, `kernel/relayflowd/src/server/wire.rs:82-85`

P2-6 correctly made an `effects` claim from a non-agent step fail closed. The symmetric claim is
still accepted: an `llm` completion may pass `started_pins` / `end_pins`, which are journaled into
`StepCompletedPayload` unchecked. Harmless today — `apply_step_completed` only reads `end_pins` when
the step is an agent step (`state.rs:248-252,277-279`), so the pin chain cannot be corrupted — but
it journals a claim about surfaces the step never declared (Appendix A rule 1), which is exactly
what the `effects` branch now refuses. Reject them in the same branch.

## 6. What this package genuinely delivers

Ladder rung (c) is real mechanism, not modelling. `ensure_supported`'s blanket agent refusal is
gone; agent steps dispatch over the existing out-of-band worker path; `step.attempt.started` carries
per-surface opaque revisions and per-stream offsets sourced from the worker and chained per surface
by the kernel; `effect.record` is a real verb returning `{deduped}` from the journal-boundary unique
key, so a second attempt's provider call is suppressed rather than detected afterwards;
`step.complete` carries the kernel's own effect facts instead of the worker's claims; all three
recovery modes change what the next attempt sees; and the crash sweep proves it against the real
binary at five kill points with exact budget accounting. The one place v0 falls short of Appendix A
rule 3 is stated in the design doc rather than left for a reader to find.

REVIEW_PASSED
