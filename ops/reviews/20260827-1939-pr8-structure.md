## Scope of the change

PR #8 introduces `flows check` (covenant-2 preflight) as a **surface** capability and adds two **inert** declarations to the kernel spec — `cli` (default/step CLI for llm/agent rungs) and `triggers` (gate-1 trigger declarations) — so the sealed bundle (decision #14) can carry and hash them. It also pins the completionReason/fail-closed discipline with a new kernel test, adds a CLI entry point, a closed failure taxonomy, and a bidirectional authoring↔kernel dialect mapping (`kernelToAuthoring`).

Files touched (structural): `kernel/relayflowd-core/src/spec.rs`, `kernel/.../spec/tests.rs`, `kernel/.../machine/tests.rs`, `sdk/src/{cli,compile,failure-kinds,index,preflight,spec,validate}.ts`, their tests, and testdata fixtures.

## Findings

### 1. The kernel stays closed and pure — no product logic leaked in  ✅

The structurally sensitive question: do `cli` / `triggers` on `RunSpec` put product logic in the kernel? No.

- `grep` across `kernel/relayflowd-core/src/**.rs` (excl. tests) shows `triggers`, `.cli`, and `TriggerSpec` appear **only in `spec.rs`**. The machine, scheduler, journal, and state modules never reference them. The kernel does not resolve a CLI, does not match or dispatch a trigger, does not spawn a process.
- The kernel's only behavior over these fields is **structural validation** — non-empty `cli` → `EmptyCli` / `EmptyStepCli`; non-empty + unique trigger ids → `InvalidTrigger` / `DuplicateTrigger`. This is the same fail-closed structural discipline already applied to step ids and is exactly what AGENTS.md rule 4 demands.
- The fields are fenced in comments that name the boundary: *"The kernel treats this as inert data; `run.start` does not invoke the surface preflight in gate 1"* and *"Inert gate-1 declarations. Matching and dispatch belong to gate 2."*
- `SURFACE.md` honestly documents the gate-1 limitation (direct `run.start` bypasses surface preflight) rather than papering over it.

This matches RFC §4 (the kernel never holds provider SDKs / no I/O in core logic), decision #13 (closed kernel vocabulary), and AGENTS.md rule 2. `budget` is already carried the same way; `cli`/`triggers` follow that precedent.

### 2. Helpers over primitives — no new kernel verb  ✅

`flows check` and preflight are **SDK surface helpers**, not kernel primitives. The three step verbs (`run`/`llm`/`agent`) are unchanged; `triggers` is **data, not a verb** (it carries no dispatch). Nothing in this PR widens the kernel language. This respects decision #13 and the spirit of gate 6 ("no `integration` primitive" — integrations are surface that compiles to kernel primitives). The preflightable-CLI contract (`<cli> auth status` → exit 0) lives entirely in the surface.

### 3. Clean I/O boundary in the SDK  ✅

`preflight.ts` (237 lines) is **pure**: it performs no I/O and consumes an injected `PreflightProbes` interface (`cli`, `executor`, `command`). Every filesystem/spawn side-effect (`spawnSync`, `readFileSync`, `which`, `accessSync`) is confined to `cli.ts`, which builds the probes and hands them in. This is the AGENTS.md "built against a simulated clock / no I/O in core logic" discipline correctly applied to the surface's pure core. The pure predicates are testable without touching the disk; the tests confirm it (probe exceptions become typed `probe_failed`, never raw text).

### 4. Fail-closed + completionReason discipline, pinned by a test  ✅

New kernel test `every_failed_run_terminates_with_declared_completion_reasons` iterates the **full** `CompletionReason` failure enum and asserts each produces a typed `StepCompletedPayload.completion_reason` and a terminal `RunCompletedPayload` carrying `RunCompletionReason::StepFailed`. No raw stack trace escapes; every failed run ends in a declared kind. The SDK side has a closed `as const` failure taxonomy (`failure-kinds.ts`) with types derived from the tuples, so an undeclared kind is a compile error (`tsc --noEmit` runs in `npm test`) — the test even records that the converse is held by the type system, not by the test alone. This is RFC covenant 2 and AGENTS.md rule 4 done right.

### 5. Fail-closed on unknown fields, both sides of the boundary  ✅

Kernel: `deny_unknown_fields` on non-flattened structs + explicit step-key checks; `TriggerSpec` denies unknown fields (a `worker` key is rejected, not guessed). SDK validator: `ROOT_KEYS` / `TRIGGER_KEYS` reject unknown keys with the nearest-valid-key vocabulary. The inverse `kernelToAuthoring` refuses kernel-only values it cannot represent (a non-default `retry` → `CompileError`), so nothing is silently dropped on the round-trip. Spec-parity tests pin the hash across the dialect round-trip.
