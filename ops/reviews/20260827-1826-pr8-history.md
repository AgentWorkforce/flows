## Blocking findings

### H1 — PR #8 still edits and immediately relies on the gate judging PR #8

The prior history transcript (`ops/reviews/20260827-1815-pr8-history.md`) failed
the patch because it changed `workflows/review-swarm.yaml` and then used that
changed workflow to certify the same PR. The repair at `c839179` does not close
that finding. It adds another behavioral setting to that gate
(`aggregate.maxIterations: 1`) while the current review run is again executing
the branch's version of the workflow.

This is not merely a stale three-dot diff caused by `main` moving. The branch
and `origin/main` carry different workflow blobs:

```
HEAD:workflows/review-swarm.yaml        f99ded2783a5169db30055a152add8432b663477
origin/main:workflows/review-swarm.yaml 446d937a218751b11fdb40256f419a8e8cd4f7c9
```

Relative to the already-landed independent gate on `main`, this PR materially
changes the judging procedure: it serializes the three lenses, makes every lens
commit its transcript, changes their dependency chain, requires each artifact
to exist in `HEAD`, and fixes the aggregate attempt count. Those changes may be
good and F0 proves why durability is needed, but they are still changes to the
judge that this PR is using as its own evidence.

The branch's own plan makes the circularity explicit:

- `ops/NEXT.md:174` puts `workflows/review-swarm.yaml` in WP-5's editable file
  list.
- `ops/NEXT.md:258-268` requires that changed workflow to be rerun against PR
  #8 and requires `SWARM_PASSED` as the package's definition of done.
- `workflows/review-swarm.yaml:85-109` is the history gate producing this very
  transcript.

That directly contradicts both settled rails:

- `AGENTS.md`: **“Never edit a gate that judges your own work.”**
- RFC-0001 §2 rule 4 and settled decision 6: a gate may not be editable by the
  agents it judges; gate definitions live outside the mutating agent's scope.

It also repeats a mistake the log already records. The WP-4 round-one review
failed a “self-certifying behavioral gate,” and the later drive-log entry
explicitly praises the repair for not editing `workflows/drive.yaml` because it
was the gate judging that work. A better self-selected judge remains a
self-selected judge.

History-consistent repair: land the transcript-durability and serialization
changes separately, under independent review, on `main`; remove them from PR
#8; then rerun the already-owned, unchanged gate against PR #8. Transcripts
produced by the branch-modified gate cannot clear this provenance defect.

`c839179` makes the WP-5 plan durable by replacing the stale WP-4-FIX contents

This is the same evidence-integrity class WP-5 exists to fix: work or evidence
