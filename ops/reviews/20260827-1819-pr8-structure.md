## Findings

### 1. The kernel stays pure — inert declarations, no product logic (PASS)

`spec.rs` adds two fields to `RunSpec` and one each to the `Llm`/`Agent` step kinds:

- `cli: Option<String>` — "Default CLI for llm/agent steps. Preflight resolves step → flow → project config before the kernel is asked to start a run."
- `triggers: Vec<TriggerSpec>` — "Inert gate-1 declarations. Matching and dispatch belong to gate 2."
- `TriggerSpec { id, executor }` with `#[serde(deny_unknown_fields)]`.

The kernel does **only** three things with them: store (serde), structurally validate (non-empty, unique trigger ids, no unknown keys), and carry them so the canonical spec can be journaled and hashed. It does **not** resolve CLIs, call CLIs, check auth, match events, dispatch, provision workers, or hold any provider SDK. Confirmed by search: **no reference to `cli`/`trigger` anywhere in the kernel outside `spec.rs`** — the execution machine (`machine/`, `exec_*.rs`, scheduler) never reads them. There is no I/O and no `tenant_id`.

This is the same "carried and journaled from submit" pattern the RFC already uses for the `budget` envelope (§1, gate 1). Carrying a gate-2 declaration in the kernel spec is consistent with the spec being the content-addressed composable unit (settled decision #14: `flows build` seals canonical spec JSON). The kernel hashing it is correct; the kernel not dispatching it is correct. The comment discipline ("Matching and dispatch belong to gate 2") names the boundary explicitly.

### 2. No primitive was added — helpers/declarations only (PASS)

RFC settled decision #13: "Three step verbs (`run`/`llm`/`agent`) + four resident verbs (`on`/`human`/`dispatch`/`done`) are the whole kernel language. Everything else … is surface that compiles to kernel primitives."

This PR adds **zero** verbs. `StepKind` remains `Deterministic | Llm | Agent`. `TriggerSpec` is a data struct, not a step type. `cli` is a string field on existing step kinds. There is no `type: integration`, no new resident verb, no kernel-level "trigger" step. The closed kernel vocabulary is exactly preserved. This is surface declaration, not a kernel primitive — precisely the helper-over-primitive discipline the RFC demands.

### 3. Fail-closed is enforced at every layer (PASS)

- **Kernel `spec.rs`:** `EmptyCli`, `InvalidTrigger`, `DuplicateTrigger`, `EmptyStepCli` `SpecError` variants; `deny_unknown_fields` on `TriggerSpec` rejects an extra `worker` key (pinned by `spec/tests.rs::preflight_data_is_fail_closed`).
- **SDK `validate.ts`:** unknown-key rejection (`ROOT_KEYS`, `TRIGGER_KEYS`, per-type step keys); version check **tightened** from a permissive semver regex to exact match against `SPEC_SCHEMA_VERSION` (stricter, fail-closed on unknown versions); empty `cli` and duplicate trigger id are errors.
- **SDK `preflight.ts`:** `cli_missing` / `cli_unauthenticated` / `cli_unresolved` / `no_executor` are refusals; a probe that **throws** becomes `probe_failed` (refusal) — never silently swallowed. Deterministic steps always leave exactly one warning (`unprovable_effects` / `command_unresolved` / `command_unprovable`); silence is explicitly not an allowed state (covenant 2: "refuses *or warns* on anything it cannot prove"). The platform-default CLI rung is declared in `SURFACE.md` but **unprovisioned at gate 1**, and a flow that reaches it refuses with `cli_unresolved` "rather than guessing" — fail-closed by design, not by accident.
- **`SURFACE.md` preflightable-CLI contract:** "preflight never sends a prompt, never spends a token, and never invokes any other subcommand"; a CLI without `auth status` is refused as unauthenticated rather than assumed healthy.

### 4. `completionReason` discipline is pinned by a gate test (PASS)

New kernel test `machine/tests.rs::every_failed_run_terminates_with_declared_completion_reasons` iterates the closed set of failure `CompletionReason`s (`VerificationFailed`, `RetriesExhausted`, `LeaseExpired`, `Crashed`, `Timeout`, `WorkerError`, `BudgetExceeded`, `Canceled`) and asserts each produces a `StepCompletedPayload` whose `completion_reason` equals the declared reason, and that the run terminates with `RunCompletionReason::StepFailed`. This is RFC covenant 2 ("every failure is one of a closed set … journaled with its `completionReason`") and AGENTS.md rule 4 ("Every completion carries a `completionReason`") turned into a crash-gate, not a doc claim. The SDK mirrors the closed-set discipline with `failure-kinds.ts`'s `as const` tuples and derived types, and `preflight.test.ts` reaches every declared refusal and warning kind.

### 5. Boundaries, coupling, single purpose, file size (PASS)

- **`preflight.ts` (221 lines)** is pure over injected probes — the file states "Environment facts are injected; this module performs no I/O." It depends only on `spec.ts`/`failure-kinds.ts` *types*. Dependency direction is clean.
- **`cli.ts` (241 lines, new)** is the I/O layer (`fs`, `spawnSync`, `yaml`) that wires real probes into `preflight`. It is the `flows` `bin` (package.json). I/O confined to the surface, pure core kept pure — correct boundary.
- **`failure-kinds.ts` (43 lines, new)** has one purpose: the closed refusal/warning taxonomy with type-level derivation.
- **`compile.ts` (389 lines)** gains `kernelToAuthoring`, the inverse of `toKernelSpec`. It is fail-closed (`requireKernelObject`, `assertKernelKeys` reject unknown keys; `validateKernelRetry` rejects bad policy). The reverse map shares the forward map's helpers and key lists; splitting it would duplicate. Under the 500-line smell threshold.
- **`validate.ts` (454 lines)** is the largest file and the largest risk surface, but still under 500 and single-purpose (authoring-shape validation). Watch this one as trigger/permissions validation grows.
- **kernel `spec.rs` (451 lines)** — under 500, single purpose (spec parse + validate).
- No file crosses the AGENTS.md 500-line design-smell line; no file mixes purposes.

### 6. Spec-hash stays environment-independent (PASS)

`testdata/hello-ladder.flow.yaml` resolves its CLI from the project default (`testdata/flows.json`) so "the canonical spec and its hash pin name no environment-specific binary and no test fixture." This keeps RFC decision #14's content-addressed bundle reproducible across machines — a structural property, not a test convenience.

## Watch-items (non-blocking, recorded for the next lens/epoch)

1. **`cli` on `llm` steps.** RFC §1 calls `llm` "a bare model call — prompt in, verified output out; no PTY, no sandbox." Adding `cli` is evidence-driven (the 2026-08-27 dogfood: gemini auth dead, unknown `cli: grok` killed a run at minute 27) and the kernel never invokes it, so the field is inert and llm's "bareness" — a kernel-execution property — is preserved. Worth tracking that the bareness invariant is about execution, not declaration; it holds today.
2. **Version check is exact-match, not a window.** `validate.ts` now rejects any version ≠ `SPEC_SCHEMA_VERSION`. RFC §7 leaves the spec-schema version window open. When a second supported version lands, this must relax to the window; until then the strictness is correct fail-closed behavior for gate 1.
3. **`isKernelSpec` heuristic** in `cli.ts` keys off `depends_on`/`max_iterations` presence in any step to detect the kernel dialect. A malformed authoring flow using snake_case keys would be misdetected as kernel shape — but `validate.ts` rejects snake_case in authoring, so it fails closed regardless. Robustness note only.
4. **`validate.ts` at 454 lines** is the file closest to the smell threshold. If trigger/permissions validation grows further, split per-shape validators out before the file crosses 500.

## Conclusion

Through the single lens of structure, PR #8 holds the line the RFC and AGENTS.md draw: a small, pure kernel with a closed vocabulary; surface declarations compiled to (not added as) kernel primitives; fail-closed behavior at every boundary; `completionReason` on every completion, pinned by a test that iterates the closed failure set; and no file grown past a single purpose or the 500-line smell threshold. No product logic entered the kernel, no primitive was added, and no file outgrew its purpose.

REVIEW_PASSED
