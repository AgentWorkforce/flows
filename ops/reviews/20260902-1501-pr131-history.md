## Verdict

**REVIEW_FAILED.** The repair correctly closes most of the prior
maintainability findings, and the exact-head Linux job is real. But the repair
replaces the Node-backed `flows` launcher with a Bun-compiled executable that
exits 0 without running the CLI. The CI smoke accepts that silent no-op because
it asserts only the exit code and not the required report.

This is not a new stylistic preference. It repeats the precise shipped-entrypoint
failure class that dominated PR #8's history: a direct-invocation guard failed
to recognize the packaged entrypoint, so `flows check` exited 0 with no output.
That history led to `realpathSync` plus explicit `bin.test.ts` output/refusal
assertions. PR #131 packages the same guarded source through a new compilation
path without carrying those assertions across the boundary.

## Blocking finding

### H1 — P0 — the packaged `flows` executable is a silent no-op, repeating PR #8's shipped-entrypoint regression

The repair compiles `sdk/src/cli.ts` directly:

```yaml
bun build sdk/src/cli.ts \
  --compile \
  --target=bun-linux-x64 \
  --outfile=dist/cloud-artifact-input/flows
```

But `sdk/src/cli.ts` deliberately runs only when its source module recognizes
itself as the direct entrypoint:

```ts
function isDirectInvocation(entryPath: string | undefined): boolean {
  if (entryPath === undefined) return false;
  try {
    return pathToFileURL(realpathSync(entryPath)).href === import.meta.url;
  } catch {
    return false;
  }
}

if (isDirectInvocation(process.argv[1])) {
  void runCli(process.argv.slice(2)).then((exitCode) => {
    process.exitCode = exitCode;
  });
}
```

Inside a Bun standalone executable, `process.argv[1]` names the executable,
while `import.meta.url` still identifies the compiled source module. The guard
returns false, so no CLI code runs. I reproduced the new packaging path from an
isolated `/tmp` copy, using another clean worktree's installed dependencies to
avoid changing this worktree:

This exact class is already part of the repository's institutional history:

```text
$ git log --all --format='%h %s' -S'isDirectInvocation' -- sdk/src/cli.ts sdk/tests/bin.test.ts
9e1d9eb WP-4 — flows check preflight (covenant 2) (#8)

```

`ops/DRIVE-LOG.md` records the original defect as: invoking the built CLI
through an npm-style symlink “exits 0 with no output because the main-module
guard compares the symlink URL with the realpath-resolved module URL.” The
repair at `5189e69` and the current `sdk/tests/bin.test.ts` then made shipped
entrypoints assert both behavior and output—for example, `CHECK PASSED` on a
valid flow and `REFUSED [cli_missing]` at exit 2 on an invalid one.

PR #131 bypasses that proven artifact test surface. Its new tests use synthetic
64-byte ELF headers for both inputs, so they establish header shape but never
execute the `flows` input. Its workflow executes the real binary but treats
exit 0 alone as success. Together those gates recreate the repository's most
expensive old false-positive: a “succeeded” tool that did nothing. That violates
AGENTS.md fail-closed rule 4, RFC covenant 2, and the historical reason
`bin.test.ts` exists.

**Minimum repair:** compile a dedicated entry module that unconditionally calls
`runCli(process.argv.slice(2))` and assigns the returned exit code, while
keeping `sdk/src/cli.ts` import-safe. Then make the Linux smoke capture the
`flows check --json` output and assert the expected report (`ok: true` and the
requested path), so an inert executable cannot pass again. A packaging test
must run the compiled artifact rather than accept a synthetic ELF header.

## Conclusion

The release lane itself fits the repo's evolution: it is the backlog's declared
next layer above the Rust daemon and TypeScript CLI, it stays outside the pure
kernel, it does not confuse a runtime archive with a flow bundle, and the repair
honestly resolves most of the prior contract findings.

The actual shipped CLI, however, is inert. Because this repeats a documented
historical failure and the current smoke again mistakes exit 0 for useful work,
the exact head cannot pass the history lens.

REVIEW_FAILED
