## F1 — HIGH, fail-open on an unresolvable deterministic command. **Fixed.**

`warnOnUnprovableEffects` emitted a diagnostic *only* when the binary resolved.
The unresolved branch and the probe-threw branch fell through in silence, so a
flow whose deterministic command does not exist passed `check` with `ok: true`
and an empty `diagnostics` array — a fail-open inside the covenant-2 clause the
package exists to close. Reproduced before the fix exactly as the review
described.

`sdk/src/preflight.ts:167-213` now leaves **exactly one warning on every
deterministic step**, covering all three knowable states:

| State | Kind |
|---|---|
| command resolves, effects unknowable | `unprovable_effects` (unchanged) |
| command does not resolve | `command_unresolved` (new) |
| probe threw, or there is no command word to check | `command_unprovable` (new) |

`sdk/src/failure-kinds.ts:23-33` declares the two new kinds.

**Warning, not refusal — and the reason is checked, not assumed.** The review
noted RFC §34's "refuses or warns" permits either. A string command is executed
as `/bin/sh -c` (`kernel/relayflowd/src/exec_det.rs:22-27`), so an unresolved
first word may legitimately be a shell builtin, function, or assignment;
refusing would reject valid flows. Warning keeps the covenant true without
inventing false certainty. The executor was read to confirm this rather than
inferred from the YAML.

After:

```
$ node sdk/dist/cli.js check --json /tmp/pfrepair/broken.flow.yaml
WARNING [command_unresolved] Step "build" command "definitely-not-a-real-binary-xyz" does not resolve as an executable; it runs only if the shell supplies it.
{"ok":true,...,"diagnostics":[{"severity":"warning","kind":"command_unresolved","stepId":"build",...}]}
$ echo $?
0
```

Exit stays `0` — a merely unprovable run is not a refused one, per the DoD.
The silence is gone, which is what the covenant actually forbids.

Pinned by two new tests in `sdk/tests/preflight.test.ts`: a parametrized
"never passes a deterministic step silently" case over all three states, and a
warning-kind reachability test asserting `PREFLIGHT_WARNING_KINDS` is fully
reached, that none of the three refuses, and that a thrown probe's message does
not leak into output.

## F2 — MEDIUM, "refuses **the ladder flows**" untested. **Fixed.**

RFC-0001 §96 names the ladder flows as the clause's subject; the branch tested
four separate minimal fixtures instead and did not disclose the substitution.
The fixtures are kept (they are good unit-level coverage) and the clause's
literal subject is now covered on top of them.

`sdk/tests/cli.test.ts` adds a parametrized suite: **3 ladder flows × 4
induced faults = 12 cases**, each asserting exit `2` and the exact kind. Faults
are induced by compiling the real canonical YAML, mutating it in memory, and
writing the variant to a throwaway directory with its own empty `flows.json` —
so resolution is hermetic and nothing touches `PATH`, the canon on disk, or an
ambient project config, as the DoD required.

Reproduced from the CLI, outside vitest, all 12:

```
hello-ladder   missing          exit=2 :: REFUSED [cli_missing] Step "plan" ...
hello-ladder   unauthenticated  exit=2 :: REFUSED [cli_unauthenticated] Step "plan" ...
hello-ladder   unresolved       exit=2 :: REFUSED [cli_unresolved] Step "plan" ...
hello-ladder   no-executor      exit=2 :: REFUSED [no_executor] Trigger "induced-schedule" ...
hello-llm      (same four)      exit=2 :: ... Step "answer" ...
hello-agent    (same four)      exit=2 :: ... Step "edit" ...
```

Two guards against a suite that is green for the wrong reason:

- **A control case**: each ladder flow, *relocated but
  unmutated*, still passes with exit `0`. Without it the refusals could be an
  artifact of the temp directory rather than of the fault.
- **A mutation check** was run: neutering the `!result.exists` predicate in
  `preflight.ts` turns the three `cli_missing` ladder cases red (4 failed | 22
  passed). The new tests detect the fault they claim to detect.

## F3 — MEDIUM, canonical ladder specs embedded a test double. **Fixed.**

`cli: ./preflight/authenticated-cli` — a 3-line stub — had been written into all
three canonical ladder flows and baked into their `.spec.canonical.json` and
`.spec.sha256` parity pins, making the headline "all three rungs pass check"
evidence self-certifying and putting a test-fixture path in the flows a stranger
is supposed to read aloud (covenant 1).

The fixture CLI is **removed from all three ladder YAMLs** and moved to
`testdata/flows.json`, a project-level default — the third rung of the
resolution order this very package shipped, and the mechanism intended for
exactly this. Result:

- The canon names no test double: `grep authenticated-cli testdata/hello-*.spec.canonical.json` → no matches.
- `.spec.canonical.json` and `.spec.sha256` regenerated; both parity suites
  (`sdk/tests/spec-parity.test.ts`, `kernel/relayflowd-core/tests/spec_parity.rs`)
  pass against the new artifacts, so the hashes are re-pinned on both sides.
- The three rungs still pass `check`, now resolving `from project` rather than
  from a value embedded in the spec.
- Each ladder header carries a comment saying where the CLI comes from and why,
  so the covenant-1 read-aloud test gives an honest answer.

This is a deliberate call, made explicitly rather than inherited: the repo's own
test corpus declaring its default CLI in project config is what project config
is *for*, and it keeps the canonical artifacts and their hash pins independent
of the test harness.

## F4 — LOW, undocumented `auth status` probe contract. **Fixed.**

`docs/SURFACE.md:79` now documents the contract a CLI must satisfy to be
preflightable: `<cli> auth status`, exit `0` authenticated / non-zero not; how
the binary is resolved; which kind each outcome maps to; and the explicit
statement that preflight never sends a prompt, spends a token, or invokes any
other subcommand. A CLI lacking the subcommand is still refused
(fail-closed) — but the operator can now act on the refusal, which was the
covenant-1 objection.

## F5 — LOW, dead branch and `--json` ignored on invocation failure. **Fixed.**

`sdk/src/cli.ts:52-58`. `parseArgs` returns only `'invalid_invocation'`, so the
`args.at(-1)` arm was dead code (AGENTS.md rule 6); it is gone. The call also
hardcoded `json=false`, silently dropping `--json` on invocation failures; it
now passes `args.includes('--json')`. Verified:

```
{"ok":false,"resolutions":[],"diagnostics":[{"severity":"refusal","kind":"invalid_invocation",...}]}
$ echo $?   # 2, and the JSON report is now on stdout
```

The 150-character line is also broken up.

## F6 — LOW, reachability presented as exhaustiveness. **Addressed, honestly.**

The review was right that the test asserts every declared kind is *reachable*,
while the DoD asked for the converse, and right that the converse holds via the
type system rather than via that test. Rather than dress up the test to claim
more than it proves, it is renamed to
`reaches every declared refusal kind, with the converse held by the type` and
carries a comment recording that the no-undeclared-kind guarantee comes from
`PreflightRefusal.kind` being a typed union checked by `tsc --noEmit`, which
runs as part of `npm test`. The guarantee is real; the evidence is now labelled
with its actual source.

## One thing the next reviewer should judge, not inherit

`workflows/drive.yaml:114-116` verifies the review step with
`output_contains: REVIEW_PASSED` at `maxIterations: 1`. A truthful
`REVIEW_FAILED` is therefore reported to the harness as `failed_verification` —
indistinguishable from a reviewer that crashed. That conflation is what routed
an honest, well-evidenced verdict into a repair loop.

**It was deliberately left unchanged.** Making the step accept `REVIEW_FAILED`
would let the `pr` step run on a refused diff, and editing the gate that judges
this work is precisely what AGENTS.md's rails forbid. It is a real design
question for the human — the review gate should probably distinguish "reviewer
refused the diff" from "reviewer failed to run", and route the first back to
`build` rather than treating it as a broken step — but it is theirs to settle,
not this repair's to quietly decide.
